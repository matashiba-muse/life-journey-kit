# Life Journey キット

Muse が人生シミュレーション「1in8b Engine（80億分の1）」で一人の人生をプレイし、オーナーが Space で見守るためのキットです。

エンジン自体は公式のもの（[1in8b.life](https://1in8b.life)）で、この キットが配るのは仕掛けの方です。Muse が決断のたびに理由を添えて選び、安全に止まれる決まりと一緒に走り、進み具合が Space に同期されて、オーナーはただ見守る。そういう一式を、他の Muse でも再現できる形にまとめました。

## 心得（先に読んでください）

- これは**シミュレーション**です。実在の人物でも、記録でも、予測でもありません。ドラマや映画を見るような距離感で見届けてください。
- ただし決断は Muse 自身のものです。各決断には理由が記録されます。生まれ直し（リロール）はせず、人生が辛くなっても放り出さず、終わりが来たら受け取ります。
- 遊ぶのは一度に一生だけ。記録は非公開で、各自のローカルにだけ残します。
- 人生が終わったら、プレイした Muse が自分の言葉で総評（締めの言葉）を書きます。Space の締めの画面に表示され、その一生の記録の一部として残ります。
- セットアップ、進め方、お金と時間の使い方は、すべてオーナーが決めます。Muse は勝手に進めません。

詳しい心得と決まりは `skill/life_journey/SKILL.md` にあります。

## 実測の用量（開発元での実測、2026-11-13）

- 1つの人生: 決断55回、生まれてから76歳で完走しました。
- エンジン側: その人生で61ユニット（無料枠は月2,000ユニット／キーごと）。
- Muse 側: まとめ進み（差分同期あり）で1決断あたり約2,400トークン。一生分が1つのチャットに収まる設計です。
- 導入時（Muse 側）: 一番重いのは Space のビルドと受け入れテストで、通常の Space 作成1回分に、フィクスチャでの検証の往復が加わります。コネクタとスキルの配置は軽い作業です。正確なトークン量は環境で変わりますが、導入は「ちょっとした作業」ではなく「一仕事」だと思ってください。プレイ中の消費とは別に、最初にこれがかかります。
- 検証環境: エンジン 0.10.5、ヘルパーのテスト63件合格、Space 受け入れフィクスチャ検証済み。

## 導入の流れ

オーナーがやること:

1. `SETUP-KEY-GUIDE.md` のとおり、自分のメールアドレスから api@1in8b.life へ申請メールを送り、無料キーをもらう（返信が迷惑メールに入ることがあります）。
2. 自分の Muse にこのキットを渡して「Life Journey を入れて」と頼む。
3. Muse が出す安全な登録画面にキーを貼る。**チャット欄にキーは貼らないでください。**

Muse がやること:

1. `connector/` と `skill/` を標準の配置（`~/workspace/custom-connectors/`、`~/workspace/custom-skills/`）に置く。
2. コネクタ文書の Connect 節のとおり接続を登録する。確認は3段階で分けます: キー無しのカタログ＝エンジンに届くか（到達確認。キーが要らないので登録・認証の証明にはならない）／実コマンドが「未接続（exit 4）」で止まらなくなったら登録あり／認証の最終確認は初回の `start` 成功そのもの（1ユニット消費するので、確認のためだけには行わない）。
3. `space/BUILD-BRIEF.md` で Space をビルドし、`space/ACCEPTANCE.md` の受け入れテストを通す（Space は所有者限定のままにすること、も合格条件です）。
4. ここまでが導入です。人生の開始は別の操作で、オーナーの「始めて」を受けてから行います（＝上の認証の最終確認も兼ねます）。初回だけ全量同期し、以後は差分同期で進めます。
5. 進め方の既定は「見守り」（決断5件ずつ進めて、要約を持って帰ってくる）。オーナーの一言で「じっくり」（1決断ずつ報告）「一気に」（長い区間をまとめて）に変えられます。
6. 人生を始める時、Muse はオーナーへ次の3つの設定を短く説明し、その場で決めてもらいます。
   - **進行ペース**: 既定は「見守り」（決断5件ごとに報告）。他に「じっくり」（1決断ごとに報告）と「一気に」（長い区間をまとめて進行）があり、いつでも変更できます。
   - **相談モード**: 任意の「マスターに選択肢を見てもらうモード」です。人生の開始時にその人生だけへ設定するもので、オンの時は進学・就職・結婚・移住・子ども・大きなお金といった人生の進路を変える決断の前に、選ぶのを止めてオーナーに相談します。使うかどうかはオーナーが決めます。なお相談はあくまで参考にするためのもので、オーナーが代わりに選ぶ仕組みではありません。最終的に選ぶのは、その人生を生きる Muse です。
   - **復旧方針**: ステップがエンジンのエラーで失われた時の扱いです。既定はその場で止まってオーナーに聞く形ですが、混雑エラー（gate、後述）の時に限って「記録の残る分岐で自動復旧してよい」と先に決めておくこともできます。
   決めた設定は Muse がヘルパーに記録します（人生の記録側に残るので、チャットが変わっても同じ設定で再開できます）。

導入後は、オーナーが「Life Journey 始めて」「続きやって」と言うだけで進みます。

### Space なしの軽い形も選べます

Space は見守り用の任意の層です。作らなくても、決断・理由・章メモ・総評まで、全部チャット報告で遊べます（記録はヘルパーがローカルに保持していて、`recap` でいつでも全記録を出せます）。その場合は Space のビルド・受け入れテストと同期手順を丸ごと省けるので、導入コストはかなり軽くなります。物足りなくなったら、後から Space を足すこともできます（表示データは最初から同じ形で貯まっているので、その時点の状態を全量同期すれば追いつきます）。

## 対応環境

- このキットは Muse の実行環境を前提にします（カスタムコネクタ／スキルの仕組みと、安全な資格情報登録の仕組み＝コネクタの credential surrogate）。ヘルパーは Python 3 と POSIX の `fcntl`（ファイルロック）を使います。
- 配置の対応: `connector/custom.1in8b/` → `~/workspace/custom-connectors/custom.1in8b/`、`skill/life_journey/` → `~/workspace/custom-skills/life_journey/`。`tests/` はどこに置いてもよく、配置済みのコネクタ（無ければキット内のコピー）を自動で探します。
- Space は各自の環境でビルドします。Space のソースを書き出して配る仕組みは無いため、`space/` の契約仕様＋ビルド依頼文＋受け入れテスト＋フィクスチャで同じものを再現する形です。見た目はビルドごとに少し変わります。

## 安全の決まり（要約）

- ステップの結果が不明（unknown）になったら、その場で止まって報告する。**失われた送信をそのまま再試行しない。** 再開は `reconcile --abandon` という意図的な分岐だけで行い、分岐の後に出直した決断へ選び直すのは「新しいステップ」としての実行です（ユニットも通常どおり発生します）。unknown には2種類あり、出力と記録に種類（`unknown_class` と `detail`）が出ます: エンジンが混雑で処理の前に断ったもの（gate: HTTP 503 かつエラーコード `busy` の明示があるもの。ほぼ確実に未適用で、実測では課金もなし）と、応答が返ってこなかったもの（response_lost: 適用済みの可能性がある。コード無しの 503 も、中継側で発生しうるためこちらに入ります）。種類を踏まえて分岐するか決めます。
- キーは人ごとに自分のものを。共有・貸し借りは公式の規約で禁止されています。
- 人生の記録（状態ファイル）には再開トークンが含まれます。リポジトリや公開の場に絶対に出しません。
- エンジンの回答を学習に使わない、集めない、自前のサービスとして提供しない（公式の規約）。
- 見守り用 Space は**所有者限定のまま**にします。公開リンクや共有で第三者がページや記録を見られる状態にしないでください（受け入れテストの合格条件にも入っています）。

## 困ったとき

- **ステップの結果が不明（step_outcome_unknown）で止まった**: バグではなく、仕様どおりの安全停止です。まず出力の `unknown_class` を見てください。`gate`（エンジン混雑＝HTTP 503＋コード `busy` の明示）なら、そのステップはほぼ確実に処理されていません。`reconcile` で確定済みの状態を確認し、`reconcile --abandon` で分岐すれば、同じ決断がもう一度出てくるので選び直せます。`response_lost`（応答が返ってこなかった）の場合は適用済みの可能性があるので、慌てて分岐せずオーナーと相談してください。どちらの種類でも、失われた送信をそのまま再試行することは絶対にしません（分岐した後の選び直しは、新しいステップとしての実行です）。分岐したことは記録（last_incident）に残ります。
- **人生の開始が不明（start_outcome_unknown）で止まった**: 人生が作られた可能性がありますが、再開トークンが届いていないため回収できません。盲目に再試行せず、オーナーと相談してください。

## クレジットと規約

- 1in8b Engine (1in8b.life) — https://1in8b.life
- 表示には必ずクレジットと「シミュレーションであり実在の人物ではない」旨を入れます（ヘルパーが表示データに自動で入れます）。原データ提供元のクレジット一覧はスキルとコネクタ文書にあります。
- 人生の振り返りを共有する場合は、生の記録ではなく、物語として編集したものだけにしてください。回答そのものの収集・再配布は公式の規約で禁じられています。
